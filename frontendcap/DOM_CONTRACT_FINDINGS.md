## What this is

The dashboard markup and the feature modules have drifted apart. Every module addresses the DOM by string id and guards its lookups (`if (el) ...`), so a deleted element does not throw — the code path just stops. Commit `6e02540` ("Fix UI/UX, responsive layout, accessibility, and workflow clarity") removed 65–85% of the dashboard markup while the modules kept addressing it, which is why several buttons in the shipped UI currently do nothing.

## How to work through this

1. Pick a feature area above. Open the module in the last column and find the `getElementById`/`setText` call sites for the listed ids.
2. Recover the markup from git: `git show 6e02540^:frontendcap/<page>.html` still contains the original block for almost every id listed here.
3. Rebuild the block against the current design system (`section-card`, `section-title`, `report-detail-grid`, `modal-actions`, `btn-primary`/`btn-secondary`/`btn-danger`), not the retired classes the old block used (`report-section`, `edit-timeline-accordion`, `modal-image-container`, `report-description`, `report-timeline` — none of which exist in `css/style.css`).
4. Verify: `npm test` must pass and `node tools/dom-contract.js` must report **no new violations**. Then shrink the ratchet with `node tools/dom-contract.js --update-baseline` and re-generate this report.

- `node tools/dom-contract.js --update-baseline` — regenerates the ratchet. **Only** after fixing findings.
- `npm run verify` — tests + audit + production build.
